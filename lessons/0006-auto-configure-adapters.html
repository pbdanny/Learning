Auto-adjust adapters safely

Yes—but separate immediate runtime fallback from learning across documents. A financial-document adapter should never rewrite its own production rules after one invoice. It should learn candidate changes from reviewed corrections, prove them on held-out data, and promote a versioned configuration through an explicit gate.

Two meanings of “auto-adjust”

ModeSafe behaviorUnsafe behavior
Within one documentTry ranked resolvers, validate, fall back to a generic adapter, or send to review.Change the global mapping because one field failed.
Across many documentsAggregate reviewed corrections, propose a draft profile, test it in shadow/held-out evaluation, then promote a version.Continuously update active production rules from unreviewed model output.

The safe learning loop

processed document + human correction
              ↓
      reviewed observation store
              ↓
cluster by vendor / class / language
              ↓
propose aliases, candidate rules, validations
              ↓
      DRAFT adapter configuration
              ↓
held-out regression evaluation
              ↓
approval → versioned ACTIVE configuration

What can be generated automatically

  • Recurring supplier/document/language profiles.
  • Label aliases such as ยอดรวมสุทธิ → total_amount.
  • Observed entity-type mappings.
  • Candidate precedence based on verified success rates.
  • Empirical confidence/review thresholds.
  • Warnings for aliases that map to several canonical fields.

What should not be auto-promoted

  • A rule learned from one document.
  • A mapping inferred only from model output without human truth.
  • A change evaluated on the same documents that generated it.
  • A vendor identity inferred from fuzzy supplier text.
  • A configuration that lowers accuracy in another vendor or language cluster.

Minimum promotion contract

GateExample policy
Reviewed supportAlias appears correctly in at least 5 distinct reviewed documents.
PrecisionAt least 98% correct mapping for high-risk financial fields.
Held-out testNo document used to discover the rule appears in the evaluation set.
RegressionNo unacceptable decrease in any vendor/language/document-class cluster.
VersioningImmutable config version, source hashes, author/approver, and rollback target.
ApprovalHuman approval before changing the active profile registry.

Google features versus your adapter

Document AI can help create or train the extraction layer. Automated schema generation can propose a custom-extractor schema from a test document; Google presents it for approval or editing. Auto-labeling can pre-populate document labels, but the labels must be reviewed and marked as labeled before they can be used for training or testing. These capabilities can reduce labeling work, but they do not define your application’s canonical record, routing policy, accounting validation, or deployment approval.

Working example

examples/adapter_config_suggester.py consumes only human-reviewed observations. It groups examples by supplier tax ID, document class, and language; then proposes aliases only when they recur across enough documents and meet a precision gate.

ReviewedObservation(
  document_id="invoice-0042",
  supplier_tax_id="0105559999999",
  document_class="invoice",
  language="th",
  canonical_field="total_amount",
  observed_alias="ยอดรวมสุทธิ",
  mapping_correct=True,
)

The output is always:

status = "DRAFT"

It never edits the active adapter registry. A separate promotion workflow must compare the draft against held-out ground truth, produce a diff, receive approval, and then activate a version.

When auto-configuration is not enough

If many layouts require brittle aliases or position rules, move the learning problem into a Custom Extractor and keep the adapter thin. The adapter still remains responsible for typed output, evidence, business validation, and review routing.

Retrieval practice

A new alias appears correctly in 12 reviewed invoices, but all 12 come from the same layout batch and no held-out examples exist. Should it become active automatically?

Reply with the decision and the missing evidence. Separate “good discovery evidence” from “safe deployment evidence.”
