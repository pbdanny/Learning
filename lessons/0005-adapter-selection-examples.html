Adapter selection: eight concrete cases

Select the most specific adapter justified by trustworthy facts. When strong facts are missing, fall back to a broader adapter; when facts conflict or profiles tie, review instead of guessing.

The adapter hierarchy

vendor + document class + language adapter
            ↓ if no exact match
    document class + language adapter
            ↓ if no exact match
       document class adapter
            ↓ if no exact match
       manual-review default

Specificity should change field-resolution rules, not the canonical output schema.

Examples

Trusted metadata can be stronger than OCR

If a supplier uploads through an authenticated portal tied to ERP vendor ID V-1042, that upstream ID may be a stronger routing fact than an OCR-extracted supplier name. Preserve provenance:

supplier_id = "V-1042"
supplier_id_source = "authenticated_vendor_portal"

ocr_tax_id = "0105559999999"
ocr_tax_id_valid = True

If the trusted vendor master and OCR tax ID disagree, do not choose one silently. Route to review with a reason such as vendor_identity_conflict.

Selection is different from field extraction

The router should use only a few stable facts. The selected adapter can then search many labels and structures:

router:
  tax ID + class + language → vendor-a-invoice-adapter

adapter:
  invoice_number candidates:
    invoice_id entity
    "เลขที่ใบกำกับภาษี"
    "Tax Invoice No."

validator:
  required invoice number
  THB currency
  net + VAT == total

Do not route using the same weak label aliases that the adapter uses to resolve fields. That creates a circular decision: the assumed adapter determines the vendor, and the assumed vendor determines the adapter.

Operational rules

  • Known vendor, wrong class: choose the class-specific adapter, not the vendor’s invoice adapter.
  • Known class, missing vendor: choose a generic class/language adapter.
  • Two equally specific matches: review and fix the profile configuration.
  • Unknown everything: preserve raw output and use the manual-review default.
  • One-off layout difference: keep the current adapter and review; create a new profile only after recurrence is demonstrated.

Retrieval practice

An authenticated portal says vendor ID V-1042, OCR extracts a valid tax ID belonging to Vendor B, and the document classifier says invoice. Which adapter should be selected?

Answer with the route and reason. The correct design does not silently trust either conflicting identity.
